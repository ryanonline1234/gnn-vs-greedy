Adjudication · re-run on one machine

Does the graph neural network beat greedy?

A paper, two formal Comments and two Replies in Nature Machine Intelligence, and nobody moving. So I re-ran it: same host, same graphs, same seeds, both sides implemented from the published sources, with an answer key.

THE CLAIM

What is actually on trial

“…the graph neural network optimizer performs on par or outperforms existing solvers, with the ability to scale beyond the state of the art to problems with millions of variables.” Schuetz, Brubaker & Katzgraber, Nature Machine Intelligence 4, 367 (2022)
“…a simple greedy algorithm, running in almost linear time, can find solutions for the MIS problem of much better quality than the GNN. The greedy algorithm is faster by a factor of 104…” Angelini & Ricci-Tersenghi, arXiv:2206.13211 (abstract); published as Nature Machine Intelligence 5, 29 (2023), whose own abstract words this differently

The measured object is the validity of a published sentence against an exact objective, not which model is better. That sentence contains two claims, and they are scored separately because they can have different answers.

Claim A · parity with existing solvers

Refuted

A degree-based greedy finds larger independent sets at every degree and every size tested, and does it up to 327,659× faster on the same machine.

Claim B · scale to millions of variables

Upheld only after repair

Reachable — but not by the published code, which builds a dense n×n matrix (3.6 TiB at n = 106). With a sparse reformulation the paper does not contain, a full run still projects to 7.3 days against greedy's 0.267 s.

Undisclosed · operating range

Fails above d ≈ 7

Past degree seven the method returns the empty set in every run. The paper's own experiments sit at degree three.

CONTROL

The measurement nobody ran

None of the five documents in the exchange — the original paper, two Comments and two Replies — separates what the network contributes from what the post-processing contributes. Both are needed to produce a reported score, and only one of them is the thing under test.

The separation is available from data already collected: compare the raw thresholded output against the score after repair and maximalization.

Where the network works, the post-processing adds almost nothing — one node in 418 at d = 3. Where the network fails, the post-processing supplies the entire score: at d = 20 the raw output is empty, so the number reported as “PI-GNN” is produced entirely by a first-fit greedy pass over the node order.

This is the sharper form of the comparison, and it forecloses the obvious objection. A reader might suspect the repair-and-maximalize step flatters the network; the decomposition shows it contributes 0.3–0.5% where the network is working, so the measured gap to greedy is the network’s own.

A second control puts an all-ones bitstring — every node selected, carrying no information about the instance — through that same pipeline. It reaches AR 0.8694 at d = 3 against the trained network’s 0.9117, and at d = 20 it wins outright (0.15880 against 0.13956). One caveat stated plainly: on an all-ones input every node has the same conflict degree, so the repair pass reduces to iterated maximum-degree deletion — a real heuristic reading the graph. The bitstring carries no information; the pipeline does. That is why the decomposition above, not this control, is the primary evidence.

A trained network scoring below an information-free input is not a hyperparameter problem: the next section exhausts a pre-registered tuning budget without moving it, and the section after that gives the mechanism.

MECHANISM

Why it fails at high degree: symmetry never breaks

Above degree seven the network's raw output — before any post-processing — is all zeros. My first explanation was wrong, and the way it was wrong is the finding.

I thought the culprit was the diagonal. The published loss is L(p) = pᵀQp with Qᵢᵢ = −1, a pure quadratic form with no linear term, so ∇L(0) = 0 exactly: the empty set is a critical point at every degree. Fixing that should rescue it. It does not. Changing the diagonal to −Σpᵢ removes the critical point, and d = 20 still returns nothing.

The real mechanism is visible when you compare the final training loss against the exact uniform optimum of the relaxed objective — the value a network that learned nothing at all would reach:

At d = 20 the predicted mean-field loss is −12.500 and the measurement is −12.499. Measured directly, the output hovers at the uniform value p* = 0.025 with 27–29% scatter and never comes within a factor of seven of the 0.5 threshold. The network is trapped at the mean-field saddle — fluctuations form, but symmetry never breaks.

A caution this page’s first draft got wrong: matching L* does not by itself prove the configuration is uniform. The loss is second-order blind to zero-mean scatter around the stationary point, and two of the three seeds land slightly below L*, which no uniform configuration can do. The trapped-at-the-saddle claim therefore rests on measuring the output vector directly (mean p = 0.0261, standard deviation 27–29% of p*, maximum 0.074 — recorded in results/pstats.jsonl), not on the loss agreement alone.

For the published quadratic diagonal, that uniform solution happens to be p = 0. So “collapses to the empty set” and “stuck at the mean field” are the same event — the formulation simply makes the symmetric solution be nothing, and the fixed 0.5 threshold then reports it as nothing. This also explains why every rescue attempt failed: learning rate, embedding width and patience do not cause symmetry breaking.

TIME

The speed gap, actually measured

The published 104 figure was never a controlled measurement. The critique timed its greedy on the authors' own laptop and read the network's times off Figure 5 of the paper it was criticising — different hardware, different conditions. Everything below is one machine, one job at a time, nothing concurrent.

SCALE

Claim B: a million variables

The reference implementation builds a dense torch.zeros(n, n) QUBO matrix. At n = 1,000,000 that is 1.0e+12 float32 entries — 3.6 TiB. The published code cannot represent the size it claims to solve. The sparse reformulation used here is mathematically identical and is what makes any test at this scale possible — a deliberate improvement in the claim’s favour.

The paper’s own rule — dim_embedding = int(sqrt(n)), hidden = dim/2 — makes the first layer a dense (n × dim) @ (dim × hidden) matmul, so arithmetic grows as n²/2 regardless of how sparse the graph is. Measured time does not track that cleanly: slower than the arithmetic below n = 105, and about 3× faster than it in the last decade, where the 14.9 GiB working set goes memory-bound.

Measured, not projected: after 1,503 s of training at n = 106 — 36 epochs, 0.27% of the schedule this model needs — PI-GNN’s output repairs to 0.37470. The information-free null control sits at 0.39527, and DGA reached 0.43295 in 0.2671 seconds.

That run was stopped by its wall-clock budget, not by convergence, so it is a lower bound on time-to-parity and nothing more. It does not show the network would never converge.

Projection, and labelled as one. Epochs-to-convergence is stable across three decades (12,361 / 14,812 / 13,321), so the epoch count transfers. Taking the count measured at the nearest size (n = 100,000), a full run at the published configuration would take 13,321 × 47.4 s = 7.31 days, against DGA’s 0.2671 s on the same instance — a factor of roughly 2.4 million×. The critique claimed 104; this same-host figure is ~236× larger, because their 104 compared their own laptop’s greedy against GPU timings read off Figure 5 of the paper they were criticising.

HONESTY

What would overturn this

Stated plainly, because a verdict that cannot be attacked is not worth much:

  • The port. The original code is DGL 0.5.3 / torch 1.7.1 and will not run on current hardware, so I ported it to plain PyTorch. The repository’s test proves the forward math equivalent to the reference — the loss to machine precision against the true asymmetric Q, the convolution to float32 epsilon — and an adversarial audit confirmed it kills every natural mutation. The training loop is outside that proof: its fidelity rests on line-by-line replication of the reference’s bookkeeping and on fresh reruns reproducing the recorded numbers digit-for-digit. One reporting deviation exists and favours the network: the port keeps the larger of the best and final bitstrings, where the reference keeps best only.
  • The threshold’s location is measured, not derived. The mean-field analysis says where a non-breaking network lands; it does not say why symmetry breaking fails only above d ≈ 6–7 — the uniform point is a strict saddle at every degree.
  • Charity where it counts. Every difference from the reference favours the network: a sparse loss it does not have, a repair-and-maximalize step it does not perform, and best-of-two-devices timing. The greedy gets none of that.
  • The mean-field result is a prediction, not a fit. −12.500 was computed in closed form before being compared to the measurement. That is the single easiest claim here to falsify, and the easiest to check.
  • Cells deliberately not run. PI-GNN at d = 5 and d = 20 for n = 105, and at d = 5 for n = 106, were cut on wall-clock grounds after the smaller sizes had already settled those cases — 2.4 hours of machine time for results predictable to three digits, or for a collapse already 10/10 consistent with a closed-form explanation. Their baselines were measured. Saying so beats leaving the gap implicit.
  • What I did not test. MaxCut — Boettcher's concurrent critique targets that, and this study is MIS only. Nor does any of this show that graph neural networks cannot do combinatorial optimisation. It shows that this relaxation, with this projection, does not.
METHOD

Reproduce it

483 measured runs on one Apple M1 Pro (10 core, 32 GB). Greedy baselines are C with a bucket queue, so the timing comparison is not distorted by a slow baseline. Instances are uniform random d-regular graphs, verified simple and exactly regular at generation. Seeds control the graph, the network initialisation and the tie-break together.

python code/test_port.py        # equivalence proof, run this first
python code/runner.py --out results/phase1.jsonl \
       --d 3 5 20 --n 1000 10000 --seeds 0 1 2 3 4
python code/collapse_sweep.py   # the operating ceiling in d
python code/sweep_tuned.py --out results/tuning.jsonl --d 3 5 20 --n 1000 --seeds 0 1 2
python code/posthoc_d20.py      # escape attempts, incl. the repaired objective
python code/verify_meanfield.py # the -12.500 prediction
python code/analyze.py
